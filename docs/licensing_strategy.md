# Licensing Strategy Note

The repository currently uses the MIT License inherited from the public research demonstrator.

MIT is intentionally permissive: recipients may generally use, modify, distribute, and commercialize the code subject to the license terms. If the goal is to sell differentiated software rather than services/support around an open-source core, review the licensing model **before publishing proprietary product layers**.

A common product boundary is:

- public/open research core
- private commercial Analyst and Integrator modules
- proprietary customer adapters, validated data pipelines, HIL integrations, reports, support, and deployment tooling

Another option is a deliberate dual-license model, but licensing choices should be reviewed with qualified counsel before release.

This document is product-planning guidance, not legal advice.
